## overview

this is the third version of awalehassan.com. the first two sat on a portfolio
template: quick to launch, and eventually full of decisions i hadn't made. v3,
"machine room", started by deleting the template.

the result is a static site. next.js writes the html at build time, cloudflare pages
serves it from the edge, and there is no server to keep alive. case studies are MDX
files, diagrams are inline SVG, and the copy, projects, gallery, and stack notes live
in one typed content file. the hero strip is the one thing fed by a live system: it
reports the homelab through the same Go service from the previous case study.

## the design

four rules carried most of it: red is only for alarms, monospace is only for machine
output, borders are hairlines instead of cards, and the page gets one orchestrated
load moment, the status strip powering on. everything else hangs off a small token
set: ink, panel, line, text, mute, cyan, alarm.

dark only, no theme toggle. type is Space Grotesk for display, Geist for body,
JetBrains Mono for data. there is no component library; the design system is a couple
hundred lines of css and a handful of components. the copy got the same treatment as
the code, written the way i'd say it, which took longer than the layout.

## architecture

the build is the deployment. a push to main triggers cloudflare pages, next renders
every page to static html, and the output goes to the edge. no runtime server, no
database, no cache to invalidate. the worst failure mode is a bad build, and the
previous deploy stays up until the new one passes.

the status strip is the interesting seam. `/api/status` is a route handler marked
`force-static`, so next runs it once at build time. it tries the stygai-status api and
falls back to the `public/status.json` snapshot committed to the repo, which is the
normal path on cloudflare's builders because they can't see the tailnet. the snapshot
itself is refreshed from the homelab on purpose and then committed. the payload
carries a `source` field, so the page can label the data honestly: `live · tailnet` in
local development, `snapshot` with its date on the public site.

development also runs on the homelab: a node container with the repo volume-mounted,
attached to the same docker network as stygai-status, and a tailscale serve preview
for the phone. no node on the host, and the dev site sees live data.

## decisions

- **static by default.** every page is html before a request exists. that removes a
  whole category of work: no server to patch, no cache to warm, no uptime to worry
  about.
- **content as data.** copy, nav, projects, gallery metadata, and the uses page live
  in `src/resources/content.ts`. case studies are one MDX file per project. adding
  this project was a content entry and a file.
- **diagrams as SVG.** the case studies draw their own diagrams inline instead of
  shipping screenshots. they inherit the page tokens, scale cleanly, and show up in a
  diff.
- **honest status.** the strip never pretends a snapshot is live. the source chip is
  part of the design, not a debug detail.
- **one load moment.** the status strip animates in once, and that is the only
  choreography on the page. everything else is static.
- **no component library.** the site is built from native elements, a few small
  components, and css tokens. nothing to upgrade but a short list of direct
  dependencies.

## what i learned

the template was scaffolding, not architecture. deleting it was the project: once the
layout was mine, the copy, the type, and the status strip all had to earn their place.

static export turned out to be a set of design constraints. no middleware, no image
optimizer, route handlers that can only run at build time. next 16 deprecates
middleware with `output: export` anyway, so the live status proxy became a
`force-static` route handler with a committed fallback. the constraint made the
boundary between build time and runtime obvious, which is exactly what the status
strip needed to be honest about.

and the hard part of a personal site is not the css. it is writing the copy in your
own voice and resisting the urge to make it sound like a company.
