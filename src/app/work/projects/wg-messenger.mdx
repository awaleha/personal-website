## overview

WireGuard gives you an encrypted tunnel between two machines for free, and wg-messenger
builds the messenger on top of it. peers are addressed by name on a private network,
messages travel directly between machines with no central server, and everything runs from
the terminal.

WireGuard handles all of the cryptography; wg-messenger deliberately doesn't reimplement it.
the Go app provides the CLI, the daemon, the message protocol, storage, and diagnostics.

## how it works

- `wgmsg init` and `wgmsg peer add` set up an identity and register peers by their
  WireGuard public key; `wgmsg up` brings the link up
- `wgmsg daemon` runs a background process that listens for and delivers messages
- `wgmsg send bob "hello over wireguard"` sends a message to a peer by name
- `wgmsg inbox` reads message history, backed by SQLite
- messages carry ACKs and delivery status, with an offline queue and retry so nothing
  is lost while a peer is away
- `wgmsg doctor` runs network diagnostics when something doesn't deliver
- a local two-node demo exercises the whole flow without touching real infrastructure

## built so far

the cobra-based CLI (`daemon`, `send`, `version`), the local daemon, and the message and
transport packages are in the repository. peer management, SQLite history, and diagnostics
are the next milestones. the project is also the backbone of a guided Go learning
assignment, so each piece lands as its own step.
