## Overview

The home server sits in a corner of the house with no monitor attached, and "is the box okay?"
used to mean an SSH session and a handful of commands. stygai-status is the answer: one Go
service that turns the machine's own internals into a tiny JSON API, so a dashboard shows
container health, hardware state, ZFS pool status, and backup freshness at a glance — and
failures reach the phone as push notifications.

It was written as a deliberate Go learning project and has run in production since day one —
stdlib-first, with `gopsutil` as the one heavyweight dependency.

## The instruments

| Endpoint | What it reports |
|---|---|
| `GET /api/v1/system` | CPU, memory, disks, load average, uptime |
| `GET /api/v1/zfs` | Pool `stag`: health, size, last and next scrub |
| `GET /api/v1/docker` | Every container with its running state and healthcheck |
| `GET /api/v1/backups` | Last run of the oldtown restic check, straight from the Healthchecks API |
| `GET /healthz` | Liveness, used by Docker's healthcheck |

## Design decisions

- **Tailnet-only, no host ports.** The API publishes no ports on the host — it lives on the
  internal Docker network and the dashboard fetches it server-side. Access control is the
  tailnet plus the network boundary.
- **Read-only everything.** `/proc`, `/sys`, and the Docker socket are mounted read-only;
  `/dev/zfs` is passed through for pool queries; Healthchecks uses a read-only API key.
- **Stdlib-first.** `gopsutil` is the only heavyweight dependency — HTTP, JSON, and flags
  are all standard library.
- **Two small binaries.** `stygai-status` serves the API; `notify` is a one-shot CLI for
  scripts, so cron jobs can push a message without speaking JSON.
- **Self-policing container.** The Docker healthcheck pings the binary itself, so Docker
  knows the service is unhealthy before the dashboard does.
- **CI from the first commit.** GitHub Actions runs the test suite on every push.

## What I learned

This was my first real Go service, and the structure it forced was the biggest lesson:
small internal packages (`zfs`, `system`, `docker`, `healthchecks`, `notifier`) with a test
per package made the code easy to grow without rewriting. Interfaces earned their keep too —
the notifier and the Healthchecks client are simple enough to fake, which made the test
suite fast and the alerting path trustworthy enough to depend on for real.
